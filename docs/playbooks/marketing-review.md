# Marketing review — 行銷審查關卡（技術 QA 抓不到的那一層）

> 宣傳片、發表片、廣告這類「要讓人想要」的影片，除了技術 QA（規格、響度、拍點、ASR、隱私），一定要有一位以**行銷／創意總監**視角審片的人（或一個專門扮演這個角色的 agent）。

## Why — 常見的失敗模式

常見情況：規格、響度、拍點、旁白、隱私全部通過，構圖也逐輪看過，但程序建模的商品看起來像漂浮的幾何塊，觀眾的第一反應是「有點怪」。技術 QA 問的是「**做得對不對**」，行銷審查問的是「**看了會不會想要**」——這兩件事完全不同，前者通過不代表後者通過。補上行銷審查之後，通常會在一兩輪內找出一批技術上「沒錯」、但會讓產品顯得廉價或讓觀眾困惑的問題。

## Gates — 放在流程的哪裡

| 時機 | 審什麼 | 結論 |
|---|---|---|
| 腳本／分鏡 | 開頭 3 秒的鉤子、每顆鏡頭要傳達的價值、文案語氣 | 改稿 |
| **半解析試渲 contact sheet** | 下面整份清單 | GO 方向／修改清單 |
| **4 張 1080p 關鍵靜態圖** | 只審最關鍵的幾格（主角畫面、高潮、CTA）在全解析度下的細節：臉、手、商品質感、文字 | GO final（之後才跑完整 render） |
| 成片（連字幕、連聲音） | 從頭到尾看一次 | 交付／小修 |

用「4 張 1080p 靜態圖」代替「先 render 整支再看」：在 CPU 機器上，一輪完整 render 要一小時以上，靜態圖只要幾分鐘。

## Checklist — 行銷審查清單

**吸引力與質感**
- [ ] 開頭 3 秒有沒有抓住人？（沒字、沒聲、只有暗場 = 會被滑走；投影場合也會冷場）
- [ ] 產品／商品看起來**讓人想要**嗎？有沒有任何東西看起來廉價、詭異、像沒做完（空白卡、剪紙圖示、無法辨識的形狀）？
- [ ] 有沒有恐怖谷：不完整或比例怪異的人形、畸形的手指？
- [ ] 色調是否和品牌一致？冷色暗場容易變「恐怖片」，暗場的色溫要配合品牌。

**文案與畫面一致**
- [ ] 把**畫面和旁白／字幕並排比對**：旁白講的功能，畫面要真的在示範那個功能（例如旁白說「一鍵產生報表」，畫面卻停在手動填表）——這種邏輯錯誤只看畫面不會發現。
- [ ] 標籤和情境要和畫面內容相符（例如畫面是夜間場景，標籤卻寫「早晨」）。
- [ ] **最有力的字眼留給高潮**：同一個標語不要在相鄰兩顆鏡頭各用一次，否則高潮時就沒有衝擊力。
- [ ] 畫面上出現的任何日期、時間、數字要真實而且彼此一致。
- [ ] 圖示能表達的不要再寫字（文字和圖示講同一件事就是重複）；標籤越短越好讀。
- [ ] 括號裡的免責或附註字樣放在字幕裡會削弱氣勢——移到畫面角落的小標。

**品牌**
- [ ] 品牌色要在**算圖後的成品**上實際取色比對，不能只看材質設定：3D 的 emission、bloom、色調映射會讓品牌色的色相或飽和度偏移。
- [ ] 字標照官方檔案取樣，不要照 brief 的文字描述。

**合規與風險**
- [ ] 沒有價格、點數、網址、真實帳號（除非刻意要放）。
- [ ] 避開之後外流會麻煩的道具或元素（受管制商品、第三方品牌 logo、可辨識的真人）。
- [ ] AI 生成的人物標示「示意」，並在 1080p 下逐張檢查臉和手。

## Techniques — 好用的修法

- **商品不要用程序建模**：有自己的商品照片時，一律做成 3D **照片卡**（圓角、柔陰影、輕微厚度、視差），比程序建模更有質感。程序建模只留給抽象元素（字標、介面、光效）。
- **同一位角色出現在多個情境時，用一致的人物，不要靠裁切「假裝同一人」**（針對照片或 AI 生成的人物素材；程序建模的人偶照 [beat-synced](beat-synced-launch-video.md) 的做法）：先做一份角色設定（幾個角度的參考圖＋臉部特寫），所有畫面都從這份設定產生。把不同人的素材統一裁成只剩局部，雖然能湊成「同一個人」，但系統性的裁切會讓整支片顯得怪異——寧可露臉、換人，也不要靠裁切硬湊。避開手部特寫（AI 手指最容易出錯）和搶戲的背景。
- **做一條故事線**：讓同一個主角貫穿每顆鏡頭（問題 → 使用 → 結果 → CTA），整支片就是一個故事，而不是功能清單。
- **同一組素材不要在畫面上扮演互相矛盾的角色**（例如「之前」和「之後」用同一張圖）。
- **審查要逐秒抽格**：每顆鏡頭只抽一兩張的 contact sheet 會漏掉一閃而過的畫面（最嚴重的問題常常只出現在一瞬間）。成片至少每秒一格。

## Delivery package — 交付包

交給業主或主管時，成品、審查紀錄、文件分資料夾放，並附一份 README：

| 資料夾 | 內容 |
|---|---|
| `video/` | 最終版（標版本號）、短預覽 GIF（可貼聊天室）、上一版（對照用） |
| `review/` | 成片逐秒抽格、關鍵靜態圖、上一版抽格 |
| `docs/` | brief（腳本、分鏡、品牌基底、備案）、旁白 QA、聲音同意紀錄 |
| `audio/` | 旁白分句檔＋timing、配樂＋節拍格線 |

README 寫：規格與響度實測、技術與行銷審查的結論、**已知事項表**（時間點、問題、建議修法、是否對外前必改）、**還需要人耳確認的項目**（腔調、音樂、混音平衡）、素材來源的注意事項。原始碼和 render 影格通常太大、又綁定製作環境，留在製作機上就好。

## Running it as an agent — 用 agent 扮演行銷審查

給它：品牌基底（官網定位、色票、字體、目標族群）、腳本、業主的回饋。要求它**自己抽格看**（不是只看別人挑好的 contact sheet）、讀旁白文字、輸出 MUST-FIX／SHOULD／NICE 三級清單，每項附具體的創意修法，最後給 GO 或修改清單。它不需要任何技術指標——要的是誠實、具體的行銷眼光。

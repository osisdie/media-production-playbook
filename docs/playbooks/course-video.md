# Course video — 16:9 課程簡介短片（Remotion＋旁白驅動）

> 1920×1080 的教學影片：簡報式畫面（步驟、重點卡、模擬畫面）、字幕寫死、鏡頭時間由旁白長度決定。範例：[`examples/course-demo`](../../examples/course-demo)。Remotion 共通做法見 [promo-video](promo-video.md)；旁白品管見 [narration QA](narration-qa.md)。

## Principles — 原則

- **時間的唯一依據是旁白**：先做好旁白，再由每句的長度排鏡頭。課程片資訊量大，先定秒數再硬塞旁白會被迫加速或刪字。
- **畫面是「教材的預告」**：只放學員上課真的會看到的東西（講義截圖、模擬的設定畫面、流程圖），不做誇大的成果畫面。
- **人耳是最後一關，但只聽清單**：自動檢查先修掉明顯的問題，再交一份含時間點的重點試聽清單。

## Planning — 規劃

- 一支片講一件事：是什麼 → 怎麼做（2–3 步）→ 要注意什麼。40–70 秒最好消化。
- 每支 6–8 句旁白，每句一顆鏡頭；中文一句約 25–45 字，英文約 12–22 個字。
- 做系列時，每支最後一句帶出下一支，可以連續播放。
- **先做一支試看**（聲音、語速、口音），確認後再量產。聲音的設定一旦修改，全部旁白都要重做，越早定案越省。
- 用真人 clone 聲音的素材放在 gitignored 的資料夾，不進公開 repo。

## Script for TTS — 給 TTS 念的稿

- **句首不要放「短詞＋標點」**：「第四步，…」「先講清楚：…」這種開頭，自回歸 TTS 常整段吞掉；改成「第四步我們…」。
- **縮寫、數字用 ASR 驗**：「Part 2」可能被念成「part 二」或漏掉；念不穩就換說法。
- **不常見的外語產品名**念不出來時，在前面加一個說明詞給模型緩衝（「一個叫做 X 的 App」）；音譯和全大寫都更差。
- 改了旁白文字，**字幕陣列一定要同步改**，並記下改了哪幾句、為什麼。
- 詳細的寫稿提示詞：[`prompts/tts-script-writing.md`](../../prompts/tts-script-writing.md)。

## Shots — 鏡頭表

```ts
// remotion/src/kit/timeline.ts
const shots = buildShots(lines, timing, fps, { firstLead: 0.35, lead: 0.25, tail: 0.45, lastHold: 1.4 });
```
- 鏡頭長度＝前置呼吸（第一句 `firstLead`，其他 `lead`）＋旁白長度＋後置呼吸 `tail`；最後一句後面再留 `lastHold` 給結尾卡。課程片可以把呼吸拉長一點（例如 0.5／0.6 秒、結尾 3 秒以上），宣傳片短一點。
- 轉場：下一顆鏡頭提早幾幀疊進來（範例用 `TRANSITION_FRAMES = 6`）。
- 字幕分段的開始時間按字數比例分配在該句旁白裡（中文一字一單位，英文單字算 2）；畫面動作（打勾、逐項出現）跟著字幕分段走。
- 旁白重做後鏡頭自動變長變短，不用手改秒數，只要重新抽幀檢查。
- 其他工具（抽幀、試聽清單的時間點）用同一套公式算，參數要和鏡頭表一致。

## Layout — 版面（1920×1080）

- 上方報頭約 100 px（課名＋本片標題）、下方字幕帶約 150 px，中間內容區 `top 140 … bottom 900`，左右各留 120。
- 字型用 FontFace＋`delayRender` 載入（例如 Noto Sans TC）；系統字型只有日韓港字形時，繁中字形會不對。
- **任何內容元素的底邊都要在字幕帶之上（約 y ≤ 880）**：底部的按鈕或標籤最容易被蓋住，抽幀時專門檢查。
- 字幕每行用陣列寫死、字級 ≥ 44 px；**行尾標點（，。；：、）顯示前去掉**，行中標點保留。
- 卡片寬度和字級一起調，避免最後一行只剩一個字；日期這類字串用 nowrap 包起來；兩張卡並排放不下時改成直向堆疊，不要縮字。

## Mock screens — 模擬畫面的安全守則
- 祕密（金鑰、密碼、token）一律遮罩，示意值也不能長得像真的。
- 帳號、公司、金額都用虛構範例；畫面上不出現個資或價格。
- 截圖嵌入前檢查瀏覽器分頁、書籤列、通知裡有沒有真實帳號。
- 影片裡的說法要和教材一致；會過時的資訊（價格、額度、版本）不要放進影片。

## Render, stills, QA — 渲染、抽幀、品管
- 規格：1920×1080、30 fps、H.264 High、yuv420p bt709、AAC 48k；2-pass loudnorm I −14、TP −1.5。範例的 `scripts/video/post.sh` 用 CRF 18＋AAC 192k（簡報式畫面檔案很小）；平台要求固定碼率時再改 CBR。
- 抽幀時間點取「每句旁白結束前 0.2 秒」（所有元素都已出現），拼成 contact sheet 一次看完：字幕帶有沒有蓋到內容、孤字、日期斷行、截圖框內文字有沒有被裁掉。
- 縮小視窗元件前先確認裡面的文字還放得下。
- 只重出有改到的那幾支；共用元件改到時，全部重新抽幀。
- 旁白：`scripts/vo/verify.py` 產生重點試聽清單；被標出的句子換 take、補抽 seed 或改寫，修完重跑驗收，確認清單變短了再重出影片。

## Pitfalls — 踩過的坑

| 坑 | 結果 | 對策 |
|---|---|---|
| 驗收只看 CER | 拖長、重複、一字一頓都通過驗收 | 加拖音、長度、語速檢查；交付附試聽清單 |
| 手動挑 take 沒看長度 | 選中的 take 比同句其他 take 長 2 秒，正是拖音的那個 | 手動挑的也要跑檢查 |
| 外語詞拉長前沒看長度 | 已經拖長的詞被再拉長 | 已過長就不拉，或只輕拉 |
| 句首「短詞＋逗號」 | 整段被吞 | 改寫句首 |
| 內容元素太低 | 被字幕帶蓋住 | 內容底邊 ≤ 880 |
| 背景重任務在前景跑超過時限 | 指令被中斷、結果遺失 | 整批工作丟背景執行，輸出寫 log |
